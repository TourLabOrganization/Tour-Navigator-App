# 체류시간 산정

투어 플래너가 관광지마다 머무는 시간을 정하고 하루 일정을 만드는 로직을 화면 코드에서 분리한 산출물입니다.

| 파일 | 내용 |
| --- | --- |
| `체류시간_산정_로직_설명.docx` | 로직 설명서 (체류 시간 · 운영시간 · 이동 추정 · 일자 창 · 배정 · 자동 코스 · 확인된 문제) |
| `체류시간_장소별.csv` | 장소 1,433곳의 권장 체류 분, 운영시간 파싱 결과, 배지, 자동 코스 후보 여부 |
| `체류시간_분류별_요약.csv` | 분류 6개별 건수 · 최소 · 중앙값 · 평균 · 최대 · 구간 분포 |
| `예시_일정_경주_2박3일.csv` | 자동 코스 + 시계 로직 실행 결과 (서울역 08:00 KTX 출발, 마지막 날 19:00 귀가) |
| `stay_schedule.js` | 로직 모듈. 체류 · 운영시간 · 이동 추정 · 일자 창 · 배정 · 시계 · 자동 코스 (의존성 없음) |
| `export_stay_csv.js` | `Tour Planner.dc.html` 의 데이터 블록을 읽어 CSV 3개를 만드는 스크립트 |
| `build_doc.js` | 설명서 docx 생성 스크립트 (CSV 결과를 표로 읽어 넣음) |

## 실행

```bash
cd "체류시간 산정"
node export_stay_csv.js          # CSV 3개 재생성 (화면 데이터가 바뀌면 다시 실행)
npm i docx && node build_doc.js  # 설명서 재생성
```

CSV 는 UTF-8 BOM 으로 저장돼 엑셀에서 바로 열립니다.

## 핵심 규칙

- 체류 시간은 장소 데이터의 `min` 필드(분). 자동 산식은 없고 사람이 정한 값입니다. 0 이면 코스에서 제외, 숙박(`stay`)은 자동 코스 후보에서 제외.
- 하루 예산 720분(09:00–21:00). 첫날은 출발 시각 + 광역 접근 시간만큼, 마지막 날은 귀가 시각만큼 줄어듭니다.
- 이동 시간은 Google 실측이 있으면 실측, 없으면 직선거리 × 1.35 에 수단별 식을 적용합니다.
- 도착 시각은 이동 → 개장 대기 → 체류 순으로 누적합니다. 자동 코스는 폐장 전에 체류를 못 마치는 후보를 건너뜁니다.

## 확인된 문제

- 전국 목록 조립 시 경주 · 거제 장소가 한 번 더 붙어 id 가 62개 중복됩니다. 여기서는 첫 레코드만 남겼습니다.
- 사용자가 직접 고른 코스의 표시 시계는 폐장 시각을 검사하지 않습니다.
- 식사 시간이 하루 창에 따로 잡히지 않습니다.
